# 批量生成中英混读单词视频

一篇考研真题阅读 → 逐句参考译文 → AI 按段落压缩成几期中文、嵌入原文单词 → 脚本校验、配音、渲染。
不依赖工作台，也不依赖 `episodes/`。脚本不写文案、不翻译，只负责切分、查词、校验、配音和渲染。

## 流程

文案准确的关键是：**先有一份逐句对齐、可信的参考译文，文案只压缩它、不重新翻译**。

1. **原文 + 参考译文** → `batch/passages/<名字>.yaml`（格式见下）。
   参考译文优先用考研机构公开的真题全文翻译，逐句贴进去核对；没有现成的，用下面的「精译提示词」让 AI 出，再人工过一遍。
   专名在 `glossary` 里定好统一译法（人名地名按新华社译名，如 Texas → 得克萨斯州/得州）。
2. **写稿** → `batch/scripts/<名字>.yaml`：把「写稿提示词」和 passage 文件发给 AI。每段正文用 `src` 标明对应原文哪几句。
3. **校验和审稿**：`batch/vb check <名字>`，除了格式和时长，还会检查
   - 学习项在对应原文句子里出现；释义能在对应的参考译文里找到（译法一致）；
   - 生成对照稿 `batch/out/<名字>/review.md`：每段并排列出原文、参考译文、正文、「还原」（英文换回释义后的纯中文）。
   把 review.md 连同「审稿提示词」发给 AI（最好换一个对话或模型）逐段挑错，改完再 check。
4. `batch/vb stills <名字>` 看静帧；满意后 `batch/vb build <名字>`。

## 准备

项目根目录先跑过 `scripts/setup.sh`（`.venv`、`data/ecdict.db`），然后：

```bash
batch/setup.sh
```

## 命令

```bash
batch/vb check  2023-eng1-text1   # 解析 + 校验 + 估算时长（不联网，几秒）
batch/vb stills 2023-eng1-text1   # 按估算时间轴渲染质检静帧和封面（不联网，每张约 1 秒）
batch/vb build  2023-eng1-text1   # 校验 → 配音 → 渲染成片和封面 → 抽帧 → 汇总
```

- 文件名可以写路径，也可以只写 `batch/scripts/` 下的文件名。
- `--only id1,id2` 只处理部分期；`build --force` 忽略缓存；`build --no-video` 只配音。
- `build` 有缓存：文案和音色没变就不重新配音；时间轴和 `video/src` 模板都没变就不重新渲染。改模板后直接重跑，会重新渲染整批。
- `build` 需要联网（edge-tts）。

产物在 `batch/out/<文件名>/`：

| 文件 | 说明 |
|---|---|
| `summary.md` | 整批汇总：时长、状态、所有 ✗ 和 ! |
| `review.md` | 对照稿（`check` 生成）：原文、参考译文、正文、还原中文逐段并排 |
| `<id>/video.mp4`、`<id>/cover.png` | 成片、封面 |
| `<id>/frames/` | 成片质检帧：第一帧、每段读完、每组复习读完、结尾全文帧 |
| `<id>/stills/` | `stills` 命令的静帧（估算时间，不是成片截图） |
| `<id>/timeline.json`、`audio.wav` | 时间轴和配音，由脚本生成，不要手改 |

`✗` 必须修，否则这一期不生成；`!` 是提醒，照常生成。

## 原文格式（batch/passages/）

```yaml
source: 出自 2023 考研英语一 阅读1      # 纸张右下角的出处，文案文件不用再写
glossary:                              # 专名、术语的统一译法
  Texas: 美国得克萨斯州（简称得州，不写“德州”）
  Pat Hardy: 帕特·哈迪（州教育委员会委员）
paragraphs:                            # 每段是一个句子列表；句号 = 段.句，如 2.1
  - - en: The weather in Texas may have cooled since ...
      zh: 最近的极端高温过后，得克萨斯州的天气或许已经转凉，……
  - - en: Pat Hardy, who sympathized with views of the energy sector, is resisting ...
      zh: 帕特·哈迪认同能源行业的观点，她正在抵制……
    - en: These would emphasise the primacy of human activity ...
      zh: 这些修改将强调人类活动在近期气候变化中的首要地位，……
```

英文句子里有 `"` 或 `: ` 时整句用单引号包起来。

## 文案格式（batch/scripts/）

改文案、看静帧，都不改画面代码。卡片宽高按抖音安全区固定，字号按全文长短自动缩放。

```yaml
defaults:
  level: 雅思             # 高考 / CET-4 / CET-6 / 考研 / 雅思 / 托福
  series: 职场黑话英语
  voice: zh-CN-XiaoxiaoNeural
  rate: "+5%"

episodes:
  - id: lowperf-1         # 输出目录名；不写则是 01、02…
    title: 大厂低绩效黑话：你只是没接住
    cover: [大厂发低绩效时，, 最爱说的几句话]   # 可选，封面大标题分行
    text: |               # 一行一段。学习词写成：英文 (词性. 语境释义)
      大厂发 underperformance (n. 低绩效) 给你，最爱用 baseline (n. 底线) 话术打压。
      领导常说：“你缺乏 ownership (n. 主人翁意识) 与 initiative (n. 主动性)，我很质疑你的 competency (n. 胜任力)。”
      其实项目停滞是高层失误，却逼你 take the fall (短语. 背锅)，让你向内求。
```

- 括号是给脚本看的，画面上不会出现在字的后面。正文只在单词下方注「词性 + 第一条释义」。
- 词性写成 `n` / `v` / `adj` / `adv`，短语写 `短语`。
- 更多释义用分号写在括号里，只出现在最后的词卡上：`(n. 低绩效；表现不佳)`。词卡还会补上词典里的其他义项和音标。
- 一行是一段朗读。空行会被忽略。
- 音标不用写。
- 写完执行 `batch/vb stills <名字>` 出静帧。满意后再 `batch/vb build <名字>`。

旧格式仍然能用：`pages` 里写不带括号的正文，`items` 里写 `[英文, 词性, 释义]`。同一期不要同时写 `text` 和 `pages`。有原文对照时，`pages` 的 `src` 仍然指向 `batch/passages/` 里的句号。

- 屈折变化（recalled、had access to）自动认出。查不到的词形写在学习项第 4 位：`[recall, v., 回忆, [recalled]]`。
- YAML 注意：含英文冒号加空格（`: `）的内容要加引号。

## 给 AI 的提示词

用其他工具批量写稿时，直接用 [`PROMPT.md`](PROMPT.md)：从获取原文、参考译文、拆分、写稿、自查到两份文件的输出格式，一段提示词全包含。下面是分步版本，适合在对话里逐步做。

### 一、精译（没有现成的机构译文时）

> 下面是一篇考研英语真题阅读原文（{年份} 考研英语{一/二} 阅读{n}）。输出 `batch/passages/<名字>.yaml`（格式见附带说明）：
> 1. 按原文分段、逐句拆开，每句一个 `en`（原文一字不改）和 `zh`（参考译文）。
> 2. 译文要忠实：不增不减，不改变逻辑关系和语气（如 barely 是「勉强」，不是「不到」）；在忠实的前提下用通顺的中文，拆长句、调语序都可以。
> 3. 先列 `glossary`：人名地名按新华社译名，首次出现用全称（Texas → 美国得克萨斯州，之后简称得州）；机构名给出中文名和一句身份说明；术语给出考研参考答案常用的译法。全文译名保持一致。
> 4. `source` 写成「出自 {年份} 考研英语{一/二} 阅读{n}」。

### 二、写稿

> 下面是一篇考研真题阅读的原文和逐句参考译文（passage 文件）。把它做成一组中英混读单词短视频文案，输出 `batch/scripts/<名字>.yaml`（格式见附带说明），`passage` 填 `../passages/<名字>.yaml`。
>
> **拆分**：按段落顺序拆成若干期，每期覆盖 1–3 个相邻段落，讲完一个完整的意思再断开；全文要讲完，不跳段。标题统一为「主题（一）」「主题（二）」……，每期前面注释对应原文第几段。
>
> **正文 = 压缩后的参考译文，不是重新翻译**：
> 1. 每段正文都标 `src`，内容只能来自这几句的参考译文：可以删修饰、合并句子、调整语序、把长句拆短，但不能改意思、不能添加原文没有的信息和评价。
> 2. 专名用 glossary 的译法，首次出现带身份（「委员帕特·哈迪」「美国国家科学教育中心」）。
> 3. 选 5–7 个学习项，把参考译文里对应的那个中文词**原位换成英文**：释义必须就是被换掉的那个中文词（参考译文写「反驳」，释义就写「反驳」）。
> 4. 换进去的英文要独立承担一个完整的意思：不要在英文前后留下会被误读成它的中文（×「委员们的政治ideology」：读的人会以为「政治」就是 ideology 的意思；写成「委员们的ideology」）。
> 5. 第二期起，第一句交代前情或抛出问题（只用前文已有的信息），让单独刷到这一期的人也能看懂。
> 6. 每期 3–6 段，全文约 150–200 个汉字（要在一屏内放下）。中文用全角标点。不写 source 字段。
>
> **学习项**：只从本期对应的原文句子里选，优先考研大纲词和真题高频词；专有名词、过于简单的词不选；整组不重复；原文词形查不到时写在第 4 位（如 `[curriculum, n., 课程, [curricula]]`）。释义不超过 8 个字，要符合词典义项（scholarship 在这里是「学术研究」不是「奖学金」）。避开 record、present 这类多音词。

### 三、审稿

先 `batch/vb check <名字>`，把 `batch/out/<名字>/review.md` 发给 AI（最好换一个对话或模型）：

> 下面是中英混读短视频文案的对照稿。每段有原文、参考译文、正文和「还原」（正文里的英文换回释义后的纯中文）。逐段检查并列出问题，每条写明段落、问题、改法：
> 1. 「还原」和「译文」意思是否一致：事实、主语、逻辑关系、程度词（barely、most、often）有没有被改；有没有原文没有的信息。
> 2. 「还原」读起来是否通顺自然，有没有翻译腔、指代不清、没交代身份就出现的人名。
> 3. 学习项释义是否符合原文语境和词典义项；英文前后有没有会被误读成它的中文。
> 4. 单独看这一期，没读过原文的人能不能看懂。
> 没有问题的段落不用列。

## 调整效果

| 想改的 | 位置 |
|---|---|
| 节奏（页间停顿、复习间隔、结尾停留） | `batch/config.py` 的 `PAGE_GAP`、`ITEM_GAP`、`OVERVIEW_HOLD` 等 |
| 字号、行距、字号自适应范围 | `batch/video/src/theme.ts` 的 `TEXT`（全文按纸张大小在 min–max 倍之间取最大能放下的字号） |
| 标题、卡片、纸张的位置 | `batch/video/src/theme.ts` 的 `LAYOUT` |
| 校验阈值（学习项数、时长、全文字数） | `batch/config.py` 的 `ITEMS_RANGE`、`BODY_RANGE`、`MAX_TEXT_WEIGHT` |
| 配色、字体 | `batch/video/src/theme.ts` |
| 版式和动画 | `batch/video/src/`：`Reading`（正文）、`Review`（词卡复习）、`Overview`（全文帧）、`Cover`（封面） |

改模板后先 `batch/vb stills <文件>` 看静帧，满意再 `build`。`cd batch/video && npm run studio` 可以交互预览（示例数据在 `src/sample.json`）。
