# 写稿规范

文案 = 一段读起来自然的中文，里面原位嵌入 5–7 个英文学习词。观众主要靠中文读懂内容，英文词和邻近的注释帮助记忆。

## 一、先判断素材类型

### A. 用户给了一段文字

**正文是压缩后的原文，不是重新创作。**

1. 先读懂原文，决定这一期讲哪几句，讲完一个完整的意思再断开。
2. 用中文写出压缩版：可以删修饰、合并句子、调语序、把长句拆短；**不能改意思，不能加原文没有的信息、评价或煽动性说法**。
3. 原文是英文：先在心里（或草稿里）译成准确的中文，再把其中的中文词原位换成英文。学习词只从原文里出现的词里选。
4. 原文是中文：直接从压缩后的中文里挑出适合学的词，换成对应的英文。
5. 专名、术语的译法全篇统一；人物、机构第一次出现时带一句身份。代词必须指代明确。
6. 内容有事实性（新闻、研究、数据）时，不要补充你没有核实过的细节。

### B. 只有主题

写一条有共鸣的短文案，见下面「内容」一节。

### 篇幅长时拆成多期

- 每期 3–6 段、约 150–200 个汉字，全文要讲完，不跳段。
- 标题统一为「主题（一）」「主题（二）」……，`id` 用 `主题词-1`、`主题词-2`。
- **第二期起，第一句交代前情或抛出问题**（只用前文已有的信息），让单独刷到这一期的人也能看懂。
- 同一篇的各期学习词不重复。

## 二、学习词怎么选

1. 5–7 个。短语算一个，整体显示、整体朗读，不拆开重复计数。
2. 优先：动词、名词、形容词；目标等级的高频词和有用的搭配。
3. 不选：专有名词；过于简单的词（school、change）；多音词（record、present、content、object、increase 等，TTS 会读错）；词典里查不到的生僻派生词。
4. 用 `python scripts/vb.py words <词> --level <等级>` 核对：词典义项、音标、级别。词库的级别标注不全，没标注不代表不适合，只作参考。
5. 不要为了凑数选生僻词。素材里没有足够合适的词，就少选几个，或者告诉用户换素材。
6. 可以出现往期用过的词；同一个词在新语境里再出现有学习价值。

## 三、原位替换（最重要）

写好中文句子后，把其中某个中文词**直接换成英文**，释义写被换掉的那个词。

```
中文：老板说要提高效率，于是安排了一个两小时的会。
混读：老板说要提高 efficiency (n. 效率)，于是 schedule (v. 安排) 了一个两小时的会。
```

规则：

1. 释义 = 被换掉的中文词，不超过 8 个字，且符合词典义项（scholarship 在「学术研究」的语境里不是「奖学金」）。
2. 把英文换回释义，句子仍然通顺、意思不变（review.md 的「还原」就是干这个检查的）。
3. **英文要独立承担一个完整的意思**，前后不能留下会被误读成它意思的中文：
   - ✗「委员们的政治 ideology」：读者以为 ideology 就是「政治」；
   - ✓「委员的 ideology」。
4. 英文用原文里的词形即可（recalled、has been resisting）；屈折变化脚本能自动识别后文再次出现的同一个词。
5. 固定搭配整体作为学习项：`sympathize with (短语. 认同)`、`take the fall (短语. 背锅)`。
6. 同一个学习词在正文里多次出现时，只在第一次写括号，释义必须一致。
7. 词性写 n / v / adj / adv；短语写「短语」。更多释义用分号接在后面，只在最后的词卡上出现：`underperformance (n. 低绩效；表现不佳)`。

## 四、内容（只有主题时）

- 新颖、有趣、贴近生活，可以自嘲和调侃普遍现象（周一、堵车、购物车）。
- 形态可选：吐槽小剧场、朋友圈 vs 现实、伪官方通知、灵魂拷问对话、拟人视角、反鸡汤、说明书体；也可以自创。
- 第一句就有画面或冲突；中间铺垫、升级；最后一句是反转或金句，≤ 15 字，不解释笑点。
- 多写具体细节和数字（闹钟响了五遍、多花两百），少用笼统形容。
- 单词放在推动剧情或抖包袱的位置；如果换回中文反而更顺，说明塞得太硬，重写。
- 不是每个稿都要搞笑。准确、自然、有内容推进比强行笑点重要。

范文（学节奏，不要照抄句式）：

> 周一闹钟响到第五遍，我的 motivation (n. 干劲) 还躺在被窝里跟自己 negotiate (v. 谈判)。地铁挤得像一场 competition (n. 竞赛)，我被 compress (v. 压缩) 成了一张照片。老板说要提高 efficiency (n. 效率)，于是 schedule (v. 安排) 了一个两小时的会，主题是：如何减少无效会议。

亮点：数字具体（第五遍、两小时）；会议主题和会议本身构成反讽；结尾不解释。

> 我是一只猫，每天的 routine (n. 例行公事) 很简单。早上五点，我准时 inspect (v. 检查) 铲屎官的脸。他假装 ignore (v. 无视) 我，我就把水杯 push (v. 推) 下桌。他终于起床，给了我一根猫条当 reward (n. 奖励)。人类真好教，三天就学会了。

亮点：视角反转（猫在训练人）；reward 放在剧情关键处。

## 五、格式要求

| 项 | 要求 |
|---|---|
| 每期段落 | 3–6 段，一行一段，每段 1–2 句 |
| 每期字数 | 约 150–200 个汉字（不含括号里的注释）；超过会被自动缩小字号，`check` 会提醒 |
| 学习词 | 5–7 个 |
| 标点 | 中文全角（，。：；？！“”）；括号注释里用半角括号和英文句点 |
| 英文空格 | 英文前后不加空格也可以，加一个空格也可以，脚本会处理 |
| 英文 | 正文里除学习词外不要出现英文；评分字母、数字缩写（B+、GDP）可保留 |
| 标题 | `title` 一行，≤ 20 字；`cover` 分两行，每行 ≤ 11 字 |
| 朗读时长 | 正文约 30–50 秒，总长 50–75 秒是较好的区间 |

## 六、禁止

- 说明文腔、流水账、说教、鸡汤口号。
- 烂梗：yyds、绝绝子、家人们谁懂啊、集美、栓Q、芭比Q、emo 了、躺平、内卷、破防了、泰裤辣、我真的会谢、你要相信、只要努力、加油吧少年、人生就是。
- 解释笑点：「是不是很真实」「哈哈哈」。
- 涉及地域、性别、职业、外貌、疾病的调侃；真实人名；品牌负面；政治；灾难；低俗；医疗建议。
- 编造来源、数据、人名。

## 七、交稿前自查

逐段对照，发现问题直接改，改完再 `check`：

1. **还原检查**：把英文换回释义，读 review.md 的「还原」——通顺吗？意思和素材一致吗？主语、事实、逻辑关系、程度词（barely、most、often）有没有被改？
2. **误读检查**：只看中文部分，有没有哪个中文词会被误认为是英文的意思？
3. **独立理解**：没看过前面内容的人，能不能明白谁、做了什么、为什么？
4. **学习词检查**：每个词都在正文里出现；释义是语境义、≤ 8 字；没有多音词；整组不重复。
5. **格式检查**：全角标点；YAML 缩进正确；`text: |` 下每行缩进一致；含 `: ` 或引号的内容要整行加引号（或用 `|` 块）。
